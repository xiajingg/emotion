## Product Design

When doing product design, UX decisions, feature planning, growth work, or roadmap prioritization, apply the AARRR framework before accepting or implementing a user-suggested feature. Identify whether the idea improves acquisition, activation, retention, referral, or revenue; define the behavioral hypothesis and success metric; and push back with a better alternative when the suggestion does not support a meaningful product outcome.

## Coding Delivery

When code changes are completed, explicitly tell the user what operational steps are needed before they can see the result. Include backend restarts, frontend rebuilds or recompilation, database SQL execution, dependency installation, cache clearing, configuration updates, or any other required action.

Also state what result the user should expect after those steps, such as the page, feature, API behavior, or data change that should become visible. Do not leave the user waiting without a clear verification path.
